# 从组件到页面：组合配方与验收

按页面任务读取一个配方；不用同时安装每个来源。来源参考负责真实条目和版本，本文件负责组合顺序。先把内容和静态布局做好，再加解决明确问题的交互。

## 设置 / 表单：让完成路径清楚

目标：看懂分组 → 填写 → 提交 → 知道结果并能恢复错误。

- 底座用项目现有 Label、Input、Select、Button；已有 HeroUI 就沿用同版本 TextField/Form，已有 shadcn 就沿用对应基础组件，不并装第二套。
- 按业务任务分组，每组标题、说明和字段有稳定的间距；辅助信息靠近字段，错误原位出现。恢复/取消弱于保存；小屏单列，按钮与表单结果相邻。
- 需要复杂上传、日期或颜色选择时查 Kibo 的对应条目；需要输入微交互时查 Bencho label-input/OTP，确认示例没有用假结果替代验证。
- 按钮状态连续可吸收 Dissolve morph-button 的方法，或复用现有 pending；不为一颗按钮引入原生引擎。加载不改变按钮宽度、不阻止更正错误。
- 验收：标签关联、键盘提交、空值/服务器错误、恢复、重复提交、保存后刷新。视觉调整不能悄悄改变已有数据契约。

## 数据后台：让数据可扫读、可行动

目标：先知道当前情况 → 缩小范围 → 找到记录 → 安全执行操作。

- BoardUI Stat Cards、Data Table、Notification Center 可作页面级组合；已有 HeroUI Table 则沿用排序/选择/分页体系。Kibo Table/Gantt/Kanban 只在业务确有该视图时补齐。
- KPI 的单位、时间范围和变化语义明确。先写标题与表格工具栏，再安排筛选/结果数/批量操作。密度来自对齐和一致行高，不来自把所有字号缩小。
- 表格用真实稳定ID，服务端排序/筛选/分页保持同一数据源；切换视图共享筛选和选中状态。窄屏可为表格提供明确的局部滚动区，页面本身不横向溢出。
- 验收：零条、长名称、大数量、加载/错误/权限禁用；键盘选择、排序、批量操作防重复；单位/时区与导出一致。

## 落地页：先建立主张，再组织证据

目标：一句话理解价值 → 看到可信例子 → 找到下一步。

- 先排 Hero 标题、说明、一个主要CTA与产品内容；把次要信息放在下一阅读层。Watermelon 的 Hero/Announcement/Auth 等区块用于构图比较；不能把目录出现当源码已核实。
- Magic UI BentoCard 或 Aceternity BentoGrid 可组织差异化功能，但三个同权重点用普通三列更合适；窄屏按内容优先级堆叠，不用固定高度挤压长文案。
- React Bits SplitText/AnimatedContent、Magic UI TextAnimate 只选择一种标题/进入方式。持续背景先检查文字对比、移动性能和减少动态效果；必要时完全静态也应有设计感。
- 展示数字可选 Magic NumberTicker 或 React Bits CountUp；结果值必须真实，减少动态效果下直接显示终值。截图、客户标志和照片使用真实授权素材，不假造产品背书。
- 验收：首屏阅读顺序、CTA去向、长标题/无图、320px、深浅色、滚动与动态降级。页面有节奏不等于每屏都换一种动效库。

## AI / 内容工具：反馈真实，保留控制

目标：理解当前状态 → 继续或取消 → 看到结果 → 错误可重试。

- BoardUI Agent Chat/Thinking/Log 组织消息与可见任务事件；Libraries.dev Beam/Voice Ring 或 Dissolve thinking-orb 只增强真实生成/收音状态。不要把可见“思考”样式当真实模型思维链。
- Bencho context-meter 显示真实用量；voice-note/time-scrubber 配实际媒体，image-compare 配获授权的前后图片；原生演示不自动成为 Web 组件。
- 空闲、等待、流式输出、成功、失败、取消分别定义；连续性来自同一对象/控制的位置稳定，不要求所有变化都粒子化。声音默认关闭，触屏操作不能只靠 hover。
- 验收：流式中断、失败重试、路由切换、滚动保持、长消息、无麦克风权限、低动态模式。不要写模拟百分比或假“完成”状态。

## 复用决策的完成条件

每次选型至少落下一条具体决定：`页面位置 → 实际条目/本地路径 → 直接复用/适配/方法 → 数据/交互接线 → 验收结果`。没有采用外部组件也可以完成优化，但说明现有实现如何覆盖目标，不只说“保持简洁”。

整页风格一致优先于组件数量；新增组件的价值要能从真实任务和对照画面里指出。记录未选方案的实质原因（版本冲突、许可、重复能力、性能或范围），不要泛泛罗列所有来源。
