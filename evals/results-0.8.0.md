# 0.8.0 技能与页面验收

日期：2026-11-19。结论：技能格式、引用、独立场景决策及代表性React页面验收完成。11个来源均有代表条目、页面组合、源码/依赖入口、接线与验收方法；这不等于所有组件都已安装、所有框架都已支持。

## 来源吸收

本轮补齐 BoardUI、HeroUI、Kibo、Libraries.dev、Watermelon、React Bits、Animate UI、Magic UI、Aceternity 九站的代表组件与组合方法，并保留 Bencho/Dissolve 深读。每站参考记录当前证据和缺口。

关键修订：HeroUI v3用compound API且为Apache-2.0；Animate UI当前v2文档不能用v1实现冒充；Watermelon auth-01只是表单展示，不是认证服务；Kibo Dropzone只是输入/拒绝处理，不负责上传。Aceternity当前单项源码授权未闭合时不自动复制，页面配方仍可借鉴构图，实测改用MIT明确的Magic UI。

新增设置/表单、数据后台、落地页、AI/内容工具四类配方。选择以任务关系和现有能力为主，不以组件数量或装饰特效为目标。新增必要依赖按兼容性与范围判断，不再用“一颗组件最多一个依赖”的硬阈值阻止复用。

## 独立场景验收（只读推演）

独立Agent读取候选技能，对4个请求给出真实选型与接线方案：HeroUI v3设置精修、Bencho收藏服务端恢复、原生CSS整页改版、shadcn日期/上传选型。

发现并修订：依赖硬阈值与源码复用冲突；Like内部状态不等于受控服务端状态；README与来源证据需一致；Watermelon原访问缺口不能覆盖已读auth-01。独立推演不计作运行或视觉验收。

## 真实页面验收环境

隔离临时夹具：React 19.3.1、TypeScript 5.9.3、Vite 6.4.6、Tailwind 4.3.5、framer-motion 12.43.0。没有接用户生产账户、云存储或外部业务。

- 设置精修：沿用现有HTML控件，调整字阶、分组、间距、按钮权重与状态。保存请求打到本机真实HTTP服务并写入临时JSON，刷新重新读取。
- 局部升级：复用Bencho Like实际TSX/CSS，保留页面结构和全局样式，增加受控状态、真实本地请求与防重。不是运行原始registry CLI，也没有安装整个Bencho。
- 整体改版：使用Magic UI BentoGrid/BentoCard真实源码，适配已有主题/按钮/图标及显式CTA；官网原先desktop hover-only CTA改成直接可见。Dissolve只采用触感/连续性方法，不声称移植其粒子引擎。

夹具的450ms延迟与503开关是可控故障注入，专用于测试pending/恢复，不属于生产组件实现。工作台内容是构造的验收数据；该试验不证明对任意真实项目都有同样审美效果，也不是模型间盲测。
