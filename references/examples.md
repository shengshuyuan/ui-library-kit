## 一句话模式下的风格判断

输入："用 ui-library-kit 优化这个页面。"（页面是带表格和筛选器的订单后台，React + Tailwind，无组件库，颜色写死在 class 里）

合理的开头两行：

```
风格判断：数据后台 / 工具型，基调克制、功能优先。当前风格：系统字体、8px 圆角、无颜色 token（灰阶出现 5 种写死值）、边框卡与阴影卡混用。
方案等级：A。无组件库且表格/筛选现有实现可用，先统一灰阶为 3 级、卡片统一用边框分层、筛选区与表格拉开间距、"导出"降为次按钮。不新增依赖。
```

## C 级建议

输入："这个后台能不能做得现代一点？"（jQuery + Bootstrap 3 + 大量内联样式，React 18 已引入但只用在两个组件，深色模式需求明确）

```
风格判断：数据后台 / 工具型。当前风格：Bootstrap 3 默认外观 + 内联样式覆盖，无 token，两套渲染方式并存。
方案等级：C。命中：无设计 token；Bootstrap 3 已停更且与 React 18 组件风格割裂；深色模式在 Bootstrap 3 上补丁成本高于迁移。
推荐方向：以已引入的 React 为底座，Tailwind + shadcn/ui（路由表中多数来源的共同前提）。先建颜色/间距/字号 token，再替换按钮、输入、卡片三类基础组件，按页面逐步迁移，旧页面不动。
本轮已做：统一现有页面的按钮主次、表格行高与筛选区间距（Bootstrap 3 内可做的 A 级改动），不改框架。
```

C 级是建议，不是执行；是否迁移由用户决定。
