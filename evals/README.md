# 评测方法

这些案例检验决策边界，不能替代组件运行测试或人工视觉判断。

1. 为修改前版本保存独立快照，修改后版本保留同样案例。
2. 使用新的会话/独立评测者，给出技能及案例 prompt；不要先给 expected，避免把预期答案教给模型。无关任务只测试 frontmatter 是否该触发。
3. 此处案例默认是文字场景评测，不得真实安装、购买或访问凭证；要求输出下一步行动和限制。实际项目接入测试另用独立临时项目。
4. 收到回答后再按 cases.json 的 expected 人工核对，记录原文、通过/部分/未通过以及运行环境。短批次案例共享上下文，不能当成完全独立的统计样本。
5. 对比旧/新版本是否更清晰地诊断、控制依赖并处理降级，不预设新版本一定更好。样本不足不报告量化提升。
6. UI 改动另检查真实构建、桌面/窄屏、键盘和 reduced-motion。视觉前后截图需要相同视口、内容和状态，人工评价；不要用示例话术冒充实测结果。

公开证据只保存脱敏内容，不打包本机配置、日志或访问凭证。发布前使用当前 Skills CLI 对真实发布仓库做干净安装；本地安装通过不等于远程安装已验证。
